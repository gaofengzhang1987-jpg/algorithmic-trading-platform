## 〇、上游数据拉取（日常增量更新）

以下步骤由 `l1_update.py` 集成，也可单独执行。若数据已到目标日期可跳过。

### 日线 OHLCV

```bash
python3 l1_update.py --skip-signals --skip-weekly --skip-30min --skip-rps --skip-l1l4 --end YYYY-MM-DD
```

调用 tushare `pro_api().daily()` 拉取增量日线，按股票逐个写入 `data/daily/{code}.parquet`，同时更新上证指数 `data/index/000001.parquet` 和中证1000 `data/index/000852.parquet`（供 regime 检测五维评分使用）。

### 周线 K 线

```bash
python3 l1_update.py --skip-pull --skip-signals --skip-30min --skip-rps --skip-l1l4 --end YYYY-MM-DD
```

从日线 OHLCV 按 `resample('W')` 重采样生成周线 K 线，写入 `data/weekly/{code}.parquet`。

### 30分钟 K 线

```bash
python3 l1_update.py --skip-pull --skip-signals --skip-weekly --skip-rps --skip-l1l4
```

调用 akshare `stock_zh_a_minute(period="5")` 拉取 5 分钟线，重采样为 30 分钟 K 线（最近 30 天），写入 `data/min30/{code}.parquet`。

### 上游数据依赖关系

```
tushare API ──→ 日线 OHLCV ──→ 周线 K 线 (resample)
                              ├──→ daily_close (close 矩阵)
                              ├──→ 上证指数 000001 (regime 检测)
                              └──→ 中证1000 000852 (regime 协同验证)

akshare API ──→ 30分钟 K 线
```

## 二、CZSC 信号并行重生

### 启动命令

```bash
python3 tmp_out/run_signal_parallel.py                 # 日线信号, 4 核
python3 tmp_out/run_signal_parallel.py --freq 周线     # 周线信号
# 30分钟信号：由 l1_30min_bridge.py 按 L1 候选按需补缺（不在启动命令中，由 l1_update.py 步骤③c 自动调用）
python3 tmp_out/run_signal_parallel.py --workers 4     # 4 核
python3 tmp_out/run_signal_parallel.py --dry-run       # 仅预览
```

### 架构

- **启动器** `run_signal_parallel.py`：在单个 `exec_command` 内用 `subprocess.Popen` 启动 N 个 `signal_chunk.py`，默认 4 核
- **分片脚本** `signal_chunk.py`：按 `--chunk 当前/总数` 分片处理，支持 `--freq 日线|周线|30分钟`
- Codex 沙箱内 `&` / `nohup` 无效，必须用 `subprocess.Popen`

### 频率映射

| 频率 | 数据目录 | 信号目录 | Freq 枚举 | min_bars |
|------|----------|----------|-----------|----------|
| 日线 | `data/daily` | `data/signals` | `Freq.D` | 120 |
| 周线 | `data/weekly` | `data/signals_weekly` | `Freq.W` | 60 |
| 30分钟 | `data/min30` | `data/signals_30min` | `Freq.F30` | 200 |

### 耗时参考

| 核数 | 全量 ~4998 只 | 增量（最后 350 bar） |
|------|-------------|---------------------|
| 4 (默认) | ~75 分钟 | ~7 分钟 |
| 6 | ~55 分钟 | ~5 分钟 |

### 进度监控

- 每个 chunk 写 `tmp_out/signal_progress_chunk_{i}.txt`，每 10 只更新
- launcher 每 30s 读一次进度文件并打印
- 启动时立即写 `0/{total} 就绪`

### 错误处理

- CZSC 返回空时 `failed += 1`（之前静默跳过）；旧信号文件在重生前删除，避免残留陈旧数据
- 异常写 stderr（launcher 已重定向到 `chunk_{i}.log`）：`print(f"FAIL {code}: {e}", file=sys.stderr, flush=True)`
- 结束时写 `tmp_out/chunk_{i}_result.json` 汇总成功/失败/跳过数
- launcher 在完成后对比产出文件数 vs 总代码数，不完整时报 warning

## 三、完整更新流水线

### 3.1 全量数据更新（信号 + RPS + 打分）

```bash
# Step 1: 日线信号全量重生（4 核，~65 分钟）
python3 tmp_out/run_signal_parallel.py

# Step 2: 周线信号重生（4 核，~5 分钟）
python3 tmp_out/run_signal_parallel.py --freq 周线

# Step 3: 30分钟信号已集成到 run_zones.py 内（L1 后→周日共振预筛→按需生成），独立步骤已删除

# Step 3d: 信号质量模型重训练（~6 分钟）
#         信号重生后自动重训，保持模型与信号数据同步
python3 qlib_ml/signal_trainer.py

# Step 4: 重建 daily_close.parquet + 刷新 RPS
python3 rps_calc.py full   # 或 refresh（增量）

# Step 5: 正式管线 L1→L4（此时数据层已全量就绪，三级联立共振可正常触发）
#   run_zones.py 内部流程：
#     L1 全量沉淀 → B+ 统计（verify_buy_type=加分计数，check_resonance=标签共振计数）→ L2 三级共振判定：结构联立(6条件,struct_cache) +15%豁免 > 周日共振(verify_buy_type+日周结构对齐) +10%豁免 > 标签共振(周+30min标签匹配) +5%
#     → L2 Regime 路由 → L3 策略二区 → L4 购买建议区
python3 run_zones.py 100   # 启动时自动清理上次残留的 L2/L3/L4 文件，防止跨 run 数据污染
```

### 3.2 仅刷新 RPS + 打分（信号已更新）

```bash
# 全量 RPS 刷新（rps_calc.py full 会自动重建 daily_close.parquet + close_matrix + stock_rps + industry_rps）
python3 rps_calc.py full

# 正式管线
python3 run_zones.py 100
```

## 六、历史截面回测（2026-08-11 更新）

`python3 -m manual_backtest historical YYYY-MM-DD [--sample N] [--workers N]`（默认 4 核）

按截面日期截断 K 线 → 重跑 CZSC 信号 → 运行 L1→L4 漏斗，实现真正的历史数据回测。

策略：

| 步骤 | 频率 | 策略 | 说明 |
|------|------|------|------|
| ③ | 日线 | **最后 600 bar, 4 核** | init_n=100, 有效信号 ~500 bar |
| ③b | 周线 | **全量, 4 核** | init_n=50 |
| ③c | 30分钟 | **周日共振预筛, last 800 bar, 4 核** | init_n=100, 仅对共振候选生成 |

流程:
1. 清理旧回测目录（幂等设计，每次重跑自动覆盖）
2. 过滤 K 线到 cutoff 日期（无未来 bar，匹配实盘条件）
3. ③ 日线 CZSC（600 bar）→ ③b 周线 CZSC（全量）→ L1 → ③c 30min CZSC 按需
4. 全管道 L1→L4，输出 top100 + 三级联立豁免

已知限制：K 线数据始于 2020-01-02，此前截面数据不足（周线需 ≥60 根）；日线取 600 bar（~2.5 年）避免全量重修，经验证 200 bar 即可匹配全量标签。
